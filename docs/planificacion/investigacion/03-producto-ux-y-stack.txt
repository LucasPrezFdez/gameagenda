=== PAIR productstack: Product/UX benchmark & 2026 tech stack

--- R5 product & UX benchmark
SUMMARY: I benchmarked 15+ trackers: Backloggd, HowLongToBeat, Playnite, LaunchBox, GameTrack, Stash, GG, IGN Playlist, Infinite Backlog, Completionator, Grouvee and Steam, plus newer 2025-26 apps (Playlogged, Tier, MyBacklog, Backlog VGO). They converge on about 5 exclusive progress states: want/backlog, playing, paused/on hold/shelved, beaten/completed, abandoned/dropped/quit. On top of that sits a separate top tier: Mastered, 100%, Completionist or Platinum. The better models keep the milestone and ownership on their own axes. Backloggd splits game toggles, a played sub-status, a 'Mastered' field and an 'Ownership' field. Infinite Backlog and Completionator store ownership details. Steam keeps wishlist, library and achievements apart. Many mobile apps instead mix Wishlist (want to buy) and Backlog (own it) into one status list.

Recommended model:
- Estado, one value: Quiero jugar (default), Jugando, En pausa, Completado or Abandonado.
- One-tap flags: Platinado, Comprado, Próximo, plus a Nota.
- 'Por comprar' and 'Pendientes que tengo' are derived filters.
- Platinado implies Completado. Dates are stamped automatically. Nothing asks for confirmation; an undo toast replaces dialogs.
- 'Completed' is ambiguous: on 2026-10-15 Steam renamed its 'Perfect Games' tab to 'Completed' (all achievements), while Backloggd uses it for beating the main objective. The app must define its labels.

Speed (tested live):
- Steam's keyless search took 259-384 ms per query and returned soundtracks and DLC.
- A local scan over 200k titles took about 5 ms median (p95 under 8 ms) in Node 24.
- So an instant omnibox (Ctrl+K or '/', Enter adds as Quiero jugar) needs a local, games-only, normalized index.
- Budgets: 50 ms per keystroke at p95, 100 ms tap feedback, INP p75 ≤200 ms, LCP ≤2.5 s, repeat start ≤2 s, no skeleton screens under 1 s.

Capture:
- MVP: paste any Steam link (store/app/ID, s.team/a/ID, which redirects there) or a bare appid.
- Web Share Target only works in installed PWAs on Chromium (Chrome Android 76+, desktop 89+). Safari/iOS and Firefox do not support it, so iPhone needs a Shortcut or a native share extension.
- Steam store pages block fetches to other origins (CSP connect-src) and block iframes (X-Frame-Options DENY). A bookmarklet must open /add?appid= instead of fetching.

Gaps and positioning: Backloggd's top unshipped requests are a native Android app (20K votes), Steam import (20K) and an iOS app (15K). Complaints center on entry friction, search ranking, slow loads, sync gaps and ads or paywalls. Compete on speed, Steam data in Spanish, Próximo plus notes, and the clean model. Leave discovery and price alerts to Steam. PSN auto-detection uses fragile unofficial APIs, so Platinado is manual in the MVP.

[R5-13] (high, CRITICAL, inference) State changes should happen automatically and be undoable. Setting Platinado also sets Completado, entering a state stamps its date, and no change asks for confirmation or extra fields. :: Rules:
- Adding a game sets Quiero jugar (addedAt).
- Jugando sets startedAt if empty; Jugando ↔ En pausa.
- Abandonado sets droppedAt; the game can come back.
- Completado sets completedAt, kept on replay (Completado → Jugando = 'Rejugando', count +1).
- Platinado ON also sets Completado (+completedAt) if needed, as one undoable action; OFF leaves Estado alone.
- Comprado never changes Estado (subscription and free-to-play games exist).
- Delete is immediate, with undo. Dates can be edited later.
This mirrors Playnite's automatic statuses and LaunchBox's rules, and avoids the 'homework' complaint. | src: https://raw.githubusercontent.com/JosefNemec/Playnite/master/source/Playnite/Database/GameDatabase.cs ; https://launchbox.featurebase.app/help/articles/6612691-game-progress-tracking ; https://dynamicdonut.bearblog.dev/tracking-sites-2 {VERDICT: confirmed}

RECS:
- Use one exclusive Estado (Quiero jugar default, Jugando, En pausa, Completado, Abandonado) plus three one-tap flags (Platinado, Comprado, Próximo) and an optional Nota. Make 'Por comprar' and 'Pendientes que tengo' filters, not states.
- Show what each label means in the app: Completado = main story or objective finished; Platinado (100%) = platinum trophy or all base-game achievements. Steam now uses 'Completed' to mean 100%.
- Make Platinado set Completado in the same undoable action. Stamp addedAt, startedAt, completedAt, droppedAt and platinumAt automatically, and never require extra fields to change state.
- Make the search box the main screen: focused on open, reachable with Ctrl+K or '/', full keyboard navigation (WAI-ARIA combobox), and Enter adds the highlighted game as Quiero jugar. Offer 'Añadir «…» como juego propio' when nothing matches.
- Ship a local, games-only Steam index (no DLC, soundtracks, demos or tools by default). Ignore case and accents, strip ®™, and map Roman and Arabic numerals. Run the search in a Web Worker and use remote Steam search only as a fallback.
- Set performance budgets and test them on a mid-range Android phone: keystroke to results ≤50 ms (p95), tap to feedback ≤100 ms, INP p75 ≤200 ms (aim for 100), first-visit LCP ≤2.5 s, cached restart ≤2 s, no skeleton or spinner for sub-second operations.
- Save locally first and render immediately. Replace every confirmation dialog, including delete, with an undo toast (about 5-8 s) and Ctrl+Z.
- Include Steam link parsing in the MVP: store.steampowered.com/app/<id>, s.team/a/<id> and a bare appid, pasted into the search box. Add the Android share target (installed PWA) next, and handle iOS with a Shortcut or a native share extension.
- For a bookmarklet or browser extension, open https://<app>/add?appid=<id> instead of calling fetch(), because Steam's CSP connect-src blocks other origins. In an extension, make network calls from the service worker and keep the content script minimal.
- Use capsule_231x87 thumbnails (~9.5 KB) with loading='lazy' and fixed width/height in a virtualized list. Use header or library art only in the detail view.
- Offer JSON/CSV export and import from day one as a backup and to avoid lock-in.
- Leave discovery, price alerts and social features to Steam and Backloggd. Keep Platinado manual in the MVP; consider Steam achievement detection later and PSN import last, since its APIs are unofficial and break.
RISKS:
- Download size and parse time of the local catalog index can hurt cold start. The real Steam catalog size, compressed payload and update strategy must come from the data research area; my benchmark used 200k synthetic names.
- Steam endpoints change: ISteamApps/GetAppList v2 is gone (ground truth), and keyless store endpoints may change or rate-limit, which affects both the catalog pipeline and the fallback search.
- Label confusion: Steam now calls 100% achievements 'Completed', and PlayStation Platinum usually excludes DLC trophies. Without clear definitions, users will misread 'Completado' and 'Platinado'.
- iPhone PWAs cannot be share targets (Safari does not support Web Share Target). If the user mainly captures on iOS, a native wrapper or share extension moves up in priority.
- Without popularity data, search ranking may bury the intended game; this was a recurring GG complaint. A ranking signal has to come from data research.
- Steam page markup changes can break an injected button, and the CSP blocks fetches from bookmarklets to other origins.
- PSN import and trophy detection depend on unofficial wrappers that need a manually renewed NPSSO token, so they are fragile and may conflict with terms of service.
- Engagement drops after the first week (reported across trackers): any extra friction when adding games, such as forms, required fields or confirmations, will kill continued use.
- Scope creep toward social features, reviews or discovery puts the app up against Backloggd and Steam's own features without an advantage.
- Complaint evidence leans on App Store reviews and blogs, some written by competitors (Achriom, SavePoint/TAG, Tier). Reddit could not be sampled because fetching was blocked.
OPEN:
- Where will the user mostly add games: on the PC (browser or Steam client) or on the phone (Android or iPhone)? This decides PWA vs a desktop or mobile wrapper and how urgent share targets are.
- Is local-only storage acceptable for the MVP, or does the user need sync between devices (and so an account) from day one?
- Should Platinado be one generic label ('Platinado (100%)'), or change per platform (Platino on PlayStation, 100% achievements on Steam, Completado on Xbox)?
- Should DLC and expansions be trackable as their own entries, or only base games?
- Is a yes/no 'Comprado' enough, or does the user want store or format details (Steam, PlayStation, físico, PS Plus, Game Pass, regalo)?
- Are ratings, dates and playtime wanted in the MVP, or only state, flags and a note?
- Should unreleased games in Quiero jugar get release-date reminders, given Steam's own wishlist and Personal Calendar already cover Steam titles?
- How many games will a typical list hold (dozens or thousands)? This sets how much list virtualization and filtering the MVP needs.
- Which platforms come after Steam (PlayStation, Switch, Xbox), and is a custom game entry acceptable for them in the meantime?

--- R6 2026 tech stack
SUMMARY: The biggest factor in making the app fast ('rápida y ágil') is to run search and writes on the device. Live data (2026-10-28): the Steam games list has 196,595 entries with an average name length of 16.7 chars. A compact appid<TAB>name snapshot is 4.95 MiB raw, 2.44 MiB gzip and 1.80 MiB brotli. On this PC (Node 24.21), accent-folding every name takes 142 ms. A brute-force substring scan takes 6-9 ms per query, and a simple word-prefix index takes 0.1-0.2 ms per query (245 ms build, ~54 MiB heap). uFuzzy's 162k-phrase benchmark shows ~5 ms per keystroke with 28 MB peak heap. Fuse.js is ~78x slower, and FlexSearch, Orama and MiniSearch keep 67-316 MB of heap. SQLite FTS5 (in Node's built-in node:sqlite, and in the official WASM build at ~0.4 MB gzip) answers in under 1 ms, but a prebuilt DB is 7.5-11.5 MiB brotli. Server-side search (pg_trgm+unaccent, D1/Turso FTS5, Meilisearch from $20/mo, Typesense) works, but every keystroke costs a network round trip plus ops and money.
Pipeline: a daily GitHub Actions cron builds the snapshot using only Node built-ins. It is free for public repos, but runs can start late or be dropped, and schedules switch off after 60 days without repo activity. Publish to Cloudflare R2 (no egress fees) or Workers static assets (free, unlimited requests). Free-tier traps: Workers Free allows 10 ms CPU, D1 Free 5M rows read/day (~25 unindexed scans), Netlify Free 300 credits (15 per deploy). Also: Vercel Hobby is non-commercial only, Supabase pauses after 7 idle days, Neon scales to zero, Render spins down, and Fly.io has no free tier.
User data: keep it local-first in IndexedDB via Dexie 4, with persist() and export. Add a thin Hono-on-Workers + D1/Turso last-write-wins sync later. Zero 1.x, Electric and PowerSync are mature, but each needs Postgres with logical replication (or PowerSync's own service) plus a sync server. That is overkill for one user's list. InstantDB Free (1 GB, never paused) is the simplest hosted backend. Safari wipes storage for sites that are not installed after 7 days of Safari use without visiting the site.
Delivery: start with a PWA. iOS 26 opens Home Screen sites as web apps, Web Push works from iOS 16.4 (declarative from 18.4), and Safari has no share_target. Tauri 2.12 desktop builds can start now on this machine (Build Tools 2022, WebView2 155 and Rust 1.99 MSVC checked live). Android needs Android Studio plus the NDK; native iOS needs a Mac.

RISKS:
- The catalog depends on IStoreService, which needs a Steam Web API key (the keyless GetAppList v2 returns 404). The jsnli dataset is third-party and unofficial, so production should use your own key and handle its terms and rate limits.
- Phones run JavaScript several times slower than this desktop (not measured). Index-based libraries can use 67-316 MB of heap on catalogs this size, which risks tab crashes on low-end Android or iOS.
- Safari ITP deletes IndexedDB/OPFS data for sites that are not installed after 7 days of Safari use without visiting them. Without sync or export, users can lose their lists.
- GitHub schedules can start late or be dropped, and they switch off after 60 days without activity on public repos. Without retries and a staleness check, the snapshot can silently go out of date.
- Free tiers and policies change: Netlify moved to credits, Vercel Hobby is non-commercial, Supabase pauses idle projects, PowerSync deactivates them, Fly.io dropped its free tier, and GitHub announced a self-hosted runner fee (Dec 2025) and then postponed it.
- Libraries still in pre-release or churn: Drizzle 1.0 RC, Prisma 8 RC on npm 'latest', TanStack DB 0.15, LiveStore 0.5, Jazz 0.20, Tauri 3 alphas, TS 7.0 without an API. Expect breaking changes.
- 6.3% of game names are CJK/Hangul. Word tokenizers and FTS5 trigram (minimum 3 chars) handle short CJK queries poorly unless there is a substring fallback.
- Tauri mobile has reported rough edges, and building for iOS natively (Tauri or Capacitor) requires macOS/Xcode, which this Windows-only setup can't provide.
- Version and date facts are moving right now: Node 26 Active LTS starts today, PostgreSQL 19 GA is due 2026-11-19, Capacitor 9 at end of Nov 2026, and CocoaPods trunk goes read-only on 2026-12-02.
