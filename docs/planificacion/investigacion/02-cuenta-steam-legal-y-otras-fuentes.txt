=== PAIR userlegal: Steam account integration, legal & third-party sources

--- R3 Steam account, auth, legal
SUMMARY: Steam should be an optional, import-only layer over a local-first to-play list. IDENTITY: Steam offers third parties only OpenID 2.0 (no OIDC; OAuth Client IDs only for Valve-chosen Cloud/Workshop partners). OpenID needs no secret; verify server-side via check_authentication POST to a hardcoded steamcommunity.com URL (CVE-2026-82183, Sept 2026, shows the cost of skipping it). Leanest hardened Node lib: steam-signin 1.0.5 (no key, returns only SteamID). Tauri: system browser + loopback (tauri-plugin-oauth) or hosted HTTPS return_to bouncing to a deep link; custom-scheme return_to untested after login. Public data needs no login: a pasted /profiles/<id> or /id/<vanity>/?xml=1 (keyless, live) suffices; OpenID matters only when a server stores data per Steam user. DATA: GetOwnedGames (key) -> 'comprado' + playtime, only if 'Game details' privacy is Public (else HTTP 200 {"response":{}}); family_shared is not 'comprado'. Wishlist is keyless (GetWishlist; GetWishlistSortedFiltered also fills Spanish store data per page) -> 'quiero jugar' suggestions. Achievements: keyless GetUserAchievements + GetGameAchievements give per-set completion -> 'platinado' at ~1 call/game; no batch endpoint works with a plain key. Achievement Sets beta (Oct 2026) redefines 100% (archived excluded, DLC sets separate, completed stays completed). ARCHITECTURE: api.steampowered.com sends no CORS headers and keys cannot ship in clients -> a small backend/proxy is mandatory for a PWA and for keyed calls from Tauri. 100k calls/day/key; IP-level 429s reported; scans must be user-triggered, incremental (rtime_last_played), cached (schema_hash). LEGAL: API ToU (2010): confidential key, privacy policy, disclose stored Steam Data + storage countries, retrieve only as the user requests, personal use, no nofollow, no implied endorsement, revocable, silent on commercial use. Use Valve's sign-in buttons + trademark notice. No user session tokens, no PICS. Images: CDN allows hotlinking (ACAO *); hotlink rather than re-host, disclose IP sharing. GDPR: SteamID + play data are personal data; basis Art. 6(1)(b); minimise; export/delete; RoPA; Spanish consent age 14 (bill to 16 pending); auth cookies exempt, analytics need consent, same for localStorage. [R3-03] (high, CRITICAL, official_doc) Relying parties that skip check_authentication or trust the asserted op_endpoint are fully bypassable; a safe verifier POSTs to a hardcoded steamcommunity.com URL, requires claimed_id, return_to and response_nonce inside openid.signed, matches return_to to its own URL, regex-checks claimed_id and accepts each assertion only once. :: CVE-2026-82183 (published Sept 2026, CVSS 8.1): WordPress 'OAuth Single Sign On' plugin <7.0.1 trusted Steam callback params without check_authentication -> attacker logs in as any non-admin user. GHSA-hhw9-35p2-q2c5 (2021-01-29, Critical): socialiteproviders/steam <1.1 accepted assertions from an attacker's own OpenID server. OpenID 2.0 s11.1: return_to scheme/authority/path MUST match; s11.4.2.1: OP 'MUST NOT issue more than one verification response for each authentication response' (anti-replay). OpenID 2.0 has no 'state': put a random value in return_to's query (it is signed) bound to a short-lived cookie to stop login-CSRF (inference). SteamID is public, never a secret. | src: https://www.sentinelone.com/vulnerability-database/cve-2026-82183/ ; https://github.com/advisories/GHSA-hhw9-35p2-q2c5 ; https://openid.net/specs/openid-authentication-2_0.html {VERDICT: confirmed}

RECS:
- Keep Steam optional and import-only: capturing a game to the to-play list (search + one tap 'Quiero jugar') must work offline/local with no login. Run the Steam import as a background job that pre-fills statuses.
- Offer two entry points. For a local-first MVP: 'Pegar perfil de Steam' (SteamID64 or vanity, no login; use /profiles/<id> directly, resolve vanity through backend ResolveVanityURL with ?xml=1 as fallback). Add 'Iniciar sesion con Steam' (OpenID via steam-signin) only once server-side sync or accounts exist.
- Run a thin backend or serverless proxy that holds the single Web API key (x-webapi-key header, secret store). It should add caching (Steam responds no-store), per-user quotas, a request queue with exponential backoff on 429, and health checks plus feature flags for undocumented endpoints. Never ship the key in the Tauri binary or the PWA bundle.
- OpenID checklist: hardcoded check_authentication POST to https://steamcommunity.com/openid/login; require claimed_id, return_to and response_nonce in openid.signed; exact return_to match; claimed_id regex ^https?://steamcommunity\.com/openid/id/(\d{17})/?$; a random state in return_to bound to an httpOnly cookie; reject reused nonces; then issue the app's own session.
- Tauri: always use the system browser, never an embedded webview login. Prefer a hosted HTTPS return_to plus a one-time code delivered by deep link (tauri-plugin-deep-link + single-instance), or a loopback callback via tauri-plugin-oauth. Test a custom-scheme return_to manually before relying on it.
- Status mapping: call GetOwnedGames (include_appinfo, include_played_free_games, skip_unvetted_apps=false, include_extended_appinfo). Mark 'comprado' only for owned apps that are not family_shared; played F2P games go to 'en biblioteca'. Turn the wishlist into suggested 'quiero jugar' items the user confirms. Use playtime_forever and rtime_last_played as 'jugando'/'jugado' hints.
- Platinado: make the scan user-triggered and limit it to has_community_visible_stats apps. Use keyless GetUserAchievements groups (base set dlcappid=0 is_completed), falling back to GetPlayerAchievements + GetSchemaForGame with the key. Re-check only apps whose rtime_last_played changed, cache schemas by schema_hash, and keep a manual override because Achievement Sets semantics may change.
- Detect private profiles up front (communityvisibilitystate or XML privacyState). Show a short Spanish guide to set 'Detalles de juegos: Publico' instead of silently importing an empty library.
- Compliance pack before launch: a Spanish, layered privacy policy listing the Steam Data stored, purposes, storage countries (prefer EU hosting) and processors (hosting, Steam CDN for images). Add in-app JSON/CSV export and 'Desconectar Steam y borrar datos', a RoPA via AEPD Facilita RGPD/Emprende, a minimum age of 14 (or 16 to be safe), the trademark notice and the Valve sign-in button, and no rel=nofollow on Steam links.
- Data minimisation: persist only steamid64 plus appid-level status, playtime and timestamps. Do not persist realname, location or raw API payloads, and prefer steam-signin over node-steam-openid (which fetches realname).
- Cookies: use only an httpOnly session cookie (exempt) plus an optional 'Mantener sesion iniciada' checkbox. Avoid third-party analytics, or gate them behind a banner with equally prominent Accept and Reject. Treat localStorage and IndexedDB the same way.
- Do not use PICS/SteamKit, Steam user access or refresh tokens, or scraping of community pages beyond the explicit ?xml=1 vanity lookup.
RISKS:
- The keyless endpoints relied on (IWishlistService/GetWishlist, IPlayerService/GetUserAchievements and GetGameAchievements, steamcommunity ?xml=1) are undocumented. They can change or start requiring a key without notice, and under the ToU Valve can revoke API access at any time.
- Per-IP throttling (HTTP 429, with reported multi-hour shadow limits) on shared serverless egress IPs could stall imports for all users at once.
- Since 2018 Steam hides game details by default, so many imports will come back empty and frustrate users unless the UX explains the setting.
- Achievement Sets have been in beta since Oct 2026. Completion semantics and the API group fields may change, so 'platinado' could stop matching Steam's own UI.
- OpenID 2.0 is legacy and its libraries are thinly maintained (passport-steam's last release was 2023). Misconfigured verifiers are a recurring CVE pattern (CVE-2026-82183).
- How Steam handles a custom-scheme return_to after login is unverified, so a Tauri flow built on it could break.
- The ToU date from 2010 and say nothing about commercial use; monetisation (ads or subscriptions) could conflict with the 'personal use' licence.
- Hotlinking Steam CDN images sends user IPs to Valve's CDN, a GDPR exposure (cf. the Munich Google Fonts ruling). Re-hosting copies instead raises copyright exposure (Renckhoff).
- Spain's minors bill may raise the digital-consent age from 14 to 16. The EU-US DPF faces a pending CJEU appeal (C-703/25 P) and a threatened noyb challenge, which affects US hosting.
- The developer reportedly needs a Steam account with games and Steam Guard Mobile Authenticator to obtain the server key.
- If users can paste any profile without logging in, the app may fetch data about third parties that was not 'requested by the end user', a gray area under both the ToU and GDPR.
OPEN:
- Will GameAgenda have server-side accounts and sync (which needs OpenID, a backend and fuller GDPR duties), or start local-first with an optional profile paste?
- Is the MVP desktop (Tauri), PWA or both? This decides loopback/deep link versus a plain web redirect, and whether keyless calls can skip the proxy.
- Does Steam deliver positive assertions to a custom-scheme or 127.0.0.1 return_to after a real login? This needs a manual test with a real account.
- Do keyless IPlayerService/GetUserAchievements calls share the per-IP limits of keyed calls, and what sustained rate is safe? This needs a controlled test.
- Should 'platinado' mean the base set only, or 100% including DLC sets? This is a product decision now that Achievement Sets exist.
- Is monetisation planned? The 2010 ToU say nothing about commercial use, so consider asking Valve before charging.
- PlayStation trophies ('platinado' implies PSN): there is no public PSN API for third parties, so this needs separate research (unofficial NPSSO-token libraries carry ToS risk).
- Wishlist 'priority' semantics (does 0 mean unranked?) are undocumented. Confirm before mapping them to an in-app order.
- What is the status of the Spanish minors bill (121/000052) in late 2026? Has the age-of-consent change to 16 been enacted?

--- R4 third-party & multi-platform sources
SUMMARY: For the later multi-platform phase, IGDB is the only source that combines all-platform coverage (PC, PlayStation, Xbox, Nintendo, retro), a free licence for non-commercial AND commercial use (commercial = free partnership + visible attribution), explicit permission to cache/mirror ('we prefer if you store and serve the data'), webhooks for incremental sync, and a documented Steam crosswalk (external_games: external_game_source=1, uid=appid; also GOG 5, Microsoft 11, Xbox 31, Epic 26, PS Store US 36). Constraints: Twitch client-credentials, 4 req/s, 8 open requests, 500 items/request, no CORS, so it must sit behind a backend; CSV dumps only for partners. IGDB also has time-to-beat (hastily/normally/completely, seconds) that replaces HowLongToBeat, and game_type/version_parent/game_status (rumored, cancelled, early access) to collapse editions and list upcoming games. Wikidata (CC0) is a free offline crosswalk: live counts today show ~129k items with a Steam appid (91% also carry an IGDB ID), ~129k ITAD, ~126k SteamGridDB, 77k MobyGames, 61k RAWG, 49k HLTB, but only ~6k each for PS Store, Nintendo eShop and Microsoft Store and ~2.5k Epic; IDs are often slugs and multi-valued (Hades: IGDB 'hades--1', 3 MobyGames ids), so identity must be many-to-many. Prices/deals: ITAD API needs an app key (no fees listed), allows commercial use if the app is public, 1000 req/5 min, Steam appid lookup (keyless /lookup/id/shop/61/v1 worked live), but its terms forbid apps that 'compete' with ITAD projects (it has Waitlist/Collection) and any data alteration. Avoid or deprioritise: Giant Bomb (API offline after leaving Fandom, live check), HowLongToBeat (no API; unofficial endpoints moved repeatedly and 429s since Sept 2026), MobyGames (paid: ~$9.99/mo hobby, $99.99+/mo commercial), RAWG (key, 20k req/month free with a backlink on every page, redistribution banned, ~$149/mo business), SteamGridDB (no PS/Xbox, terms bar automated use), SteamSpy (stale: still names 730 'Counter-Strike: Global Offensive', playtime 0), PCGamingWiki (CC BY-NC-SA). User progress: PSN trophies only via reverse-engineered NPSSO APIs that conflict with PSN ToS 10.7/5.1 (ban risk), so 'platinado' must be a manual flag (optional local-only import at most); Xbox via OpenXBL (unofficial, free 150 req/h, $5-35/mo); RetroAchievements free key. GOG/Epic have no official catalog APIs (their JSON feeds answer keyless but are undocumented). Manual/custom games are required for speed and coverage gaps.

RECS:
- Phase 1 (Steam only): keep Steam as the only catalog and source of truth; add no third-party catalog yet. Optional enrichments that do not slow capture: ITAD prices for 'quiero jugar/deseado' items (map appids with /lookup/id/shop/61/v1, then batch /games/prices/v3 with up to 200 ids, cache for hours), and later IGDB time-to-beat. Never use SteamSpy for user-facing names or playtime.
- Phase 2 master catalog: use IGDB as the multi-platform catalog (PlayStation, Xbox, Nintendo, GOG, Epic, retro). Mirror it into your own DB and local search index (IGDB prefers this), keep it fresh with webhooks (create/update/delete) plus periodic updated_at sweeps, and make every IGDB call from a backend (no CORS; never ship the Twitch client secret in a desktop/mobile/web client). If the app is ever monetized, email partner@igdb.com and add a static, visible 'Datos de juegos: IGDB.com' credit.
- Join Steam and IGDB through IGDB external_games (external_game_source = 1, uid = appid). Keep Steam authoritative for Steam-specific fields (Spanish name/description, capsules, prices) and IGDB for everything else. Write code against the new IGDB field names (external_game_source, game_type, game_status, release_region), not the deprecated enums.
- Use Wikidata (CC0) only as an offline/batch crosswalk to fill HLTB, ITAD, SteamGridDB, RAWG, MobyGames, PS Store and eShop IDs (for outbound links and de-duplication). Run it as scheduled jobs with a proper User-Agent, never on the search/typing path, and plan for the 2026-2027 WDQS backend migration.
- Identity model: games(id UUID, canonical_title, normalized_title for search, kind main/dlc/edition/bundle, parent_game_id, release_status); game_external_ids(game_id, source enum steam|igdb|wikidata|itad|gog|epic|psn|xbox|nintendo|hltb|mobygames|rawg|sgdb|manual, external_id TEXT, id_kind numeric|slug|uuid, platform, region, url, match_method exact|crosswalk|fuzzy|user, confidence, verified_at, UNIQUE(source, external_id)); game_releases(game_id, platform, date, region); game_merges(old_id -> new_id) for later de-duplication. Allow several IDs per source (MobyGames-style) and store both IGDB numeric id and slug.
- User state: user_entries(user_id, game_id, platform, want_to_play flag + priority, owned/'comprado' flag + store + date, completed date, platinum/100% date, abandoned, notes, timestamps). Keep these as independent flags/dates, not one status enum, because a game can be bought, completed and platinum at the same time.
- Allow custom/manual games as first-class entries: saving with only a title (plus optional platform) must be instant and work offline; mark it 'unlinked' and let a background matcher suggest a Steam/IGDB match that the user confirms with one tap (never auto-link fuzzy matches such as 'Hades' vs 'Hades II'). This covers catalog gaps (console store IDs are sparse: about 6k PS Store or eShop IDs on Wikidata vs about 129k Steam), plus physical, retro, mobile, unannounced or rumored games.
- Speed: put every third-party lookup behind your own cache and a per-source rate limiter (IGDB 4 rps and 8 concurrent; ITAD 1000 per 5 min; WDQS 5 parallel; SteamSpy 1 rps) with circuit breakers, so search and capture only ever hit the local index. Store raw payloads with fetched_at so you can re-map fields when providers deprecate them.
- Achievements/'platinado': keep completed/platinum as manual toggles (the source of truth). Optional imports later: Steam (official Web API), Xbox via OpenXBL (user's own key or a paid tier), RetroAchievements (user key). For PSN either skip it or do a local-only import where the user's NPSSO never leaves their device, clearly labelled unofficial and at their own risk; never collect or store NPSSO tokens on a server.
- Images and time: Steam assets for Steam games, IGDB covers (t_cover_big / t_cover_big_2x) for the rest; time-to-beat from IGDB game_time_to_beats, with HowLongToBeat only as an outbound link built from Wikidata P2816. SteamGridDB only as an opt-in, bring-your-own-key, personal-use feature.
- Avoid for legal or stability reasons: scraping HowLongToBeat; the Giant Bomb API (offline); server-side PSN credential collection (PSN ToS 5.1/10.7); SteamGridDB for automated bulk or commercial use; RAWG as a mirrored/redistributed catalog or beyond its free tier without a contract; PCGamingWiki data (NC licence); MobyGames unless you pay; scraping Epic GraphQL; GOG/Epic unofficial endpoints for core features.
RISKS:
- Single-vendor dependency: the non-Steam catalog would rely on IGDB (Twitch/Amazon), whose terms, partnership policy or schema (the enum-to-table migration) can change; adapters and a local mirror reduce the impact.
- Monetizing without an IGDB partnership and visible attribution would breach the IGDB/Twitch terms; RAWG commercial use above 100k MAU or 500k page views/month needs a contract.
- ITAD can revoke access 'at any point without notice', and its 'no competition' clause could be read against a wishlist/collection tracker.
- PSN auto-import exposes users to account bans and the app to ToS and credential-handling liability; NPSSO tokens are password-equivalent and expire about every 60 days (bad UX).
- Unofficial endpoints (HLTB, GOG catalog, Epic GraphQL, PSN, OpenXBL upstream) break without notice: HLTB's internal API moved at least three times between Aug 2025 and Oct 2026 and started returning 429s.
- Crosswalk errors: Wikidata IDs are multi-valued, slug-based and incomplete (console store IDs ~2.5k-7k), so treating them as 1:1 would cause wrong merges; fuzzy title matching can link the wrong game (sequels, remakes, editions).
- WDQS backend migration (2026-2027) may break SPARQL queries; query limits (60 s, 5 parallel per IP) make it unsuitable for interactive use.
- Image rights: SteamGridDB art is user-uploaded with unclear rights and terms that bar automated use; IGDB and Steam images remain the rights holders' property.
- Stale data sources (SteamSpy, Giant Bomb former-scheme IDs) can show wrong names or broken links if used without validation.
OPEN:
- Will GameAgenda be public and/or monetized? This decides the IGDB partnership, the RAWG tier, SteamGridDB usability and ITAD's 'commercial if public' condition.
- Is a small backend acceptable? It is required for IGDB (Twitch secret, no CORS) and for a shared catalog mirror; a purely local desktop app would need each user to create Twitch credentials.
- Current IGDB size and per-platform crosswalk coverage were not measured (needs credentials): e.g. POST /v4/games/count and /v4/external_games/count where external_game_source = 36 (PlayStation) or 1 (Steam).
- Has IGDB already removed the deprecated fields (category, media, region)? The docs still list them as deprecated on 2026-10-28; the year of the 'Feb 18 - Aug 31' migration is not shown.
- Exact HowLongToBeat terms (not retrievable with the tools used) and current SteamGridDB terms text and rate limits (only quoted second-hand).
- MobyGames Hobbyist rate (0.2 vs 1 req/s) and current prices: confirm on the live subscribe page if it is ever considered.
- Does the user actually want automatic PSN/Xbox trophy import, given the ToS risk, or is a manual 'platinado' toggle enough?
- Would ITAD consider a backlog/collection app 'competition'? Ask them before any commercial launch that shows their prices.
